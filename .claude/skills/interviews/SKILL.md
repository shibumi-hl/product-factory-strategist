# Interviews and simulated respondents

Adapted from mattpocock *to-questionnaire* (target the gap between what the
respondent knows and what we need) and gstack *office-hours* ("interest is not
demand", "the user's words beat the pitch"). Method:
`knowledge/methods/interviews.md`.

## A. Interview guide (for real interviews)

1. From open research tickets, list what we must learn.
2. Write questions about **past behaviour**, not opinions or the future:
   "Tell me about the last time you changed your tariff" — not "Would you use…?".
3. Order most important first; one idea per question; no leading wording.
4. Add a consent script and a note: no names, phone numbers or other personal
   data go into the repo; transcripts are anonymised as R1, R2…
5. Save to `projects/<slug>/interview-guide.md`.

## B. Analyzing real transcripts

1. Read each transcript in `sources/` (anonymised only).
2. Extract behaviour, workarounds, barriers and the respondent's own words.
3. Each observation = ledger row type F, source = transcript file + line/timestamp.
   A pattern across ≥3 respondents may be stated; frequency in the population may not.

## C. Simulated respondents

1. Define 3–6 personas in `projects/<slug>/personas.md`: situation, goals,
   current alternative, constraints. Base each on ledger evidence where possible
   and cite it.
2. For each persona, dispatch a `respondent` subagent with the persona and the
   guide only — never our hypotheses or preferred option.
3. Save transcripts to `projects/<slug>/synthetic/<persona>.md` with the header
   `SYNTHETIC — generated by AI, not a real person`.
4. Extract insights as ledger rows **type S**. Use them to generate new (H)
   rows or new questions for real research.

Never write "users want…", "demand exists…" or any share/percentage based on S
rows. `scripts/check.py` warns when a claim is supported only by S rows.

Done when: the guide exists, every transcript (real or synthetic) is analysed
into ledger rows with correct type, and new hypotheses are added to `questions.md`.
